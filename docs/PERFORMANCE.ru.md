# Производительность отрисовки

Шаг 1 из плана: убрать работу, которая повторялась на каждом кадре жеста. Видимое поведение в шаге 1 не менялось. С 0.7.0-rc.6 фильтры типов скрывают объекты (шаг 2 ниже).

## Что было

Камера листа жила в состоянии корневого `Tool`. Каждое событие колеса, панорамы или щипка перерисовывало весь инструмент и все карточки. `NodeCard` обёрнут в `memo`, но получал новые функции и объект `style` на каждый рендер, поэтому пропуск не срабатывал. Новый callback-ref заново подписывал каждую карточку в ResizeObserver: 1000 подписок на кадр при 1000 узлах. Для каждой связи узлы искались через `placed.find`. На каждый рендер пересчитывались локальные связи и ссылки за границей листа, JSON-ключ All-to-1 и панель «Связи с другими листами» (все листы × все связи). Перетаскивание записывало граф на каждое движение мыши: история, два индекса, проверка проекта, автосохранение.

## Что сделано

**Камера.** Во время жеста `SheetCanvas` и `OverviewCanvas` двигают сцену напрямую в DOM. В состояние React камера попадает после паузы 160 мс, при уходе указателя или размонтировании. Дискретные действия (кнопки масштаба, клавиши, «вписать») применяются сразу. Живая камера листа видна в атрибутах `data-view-x/y/k` холста; кнопки масштаба на панели используют её.

**Карточки.** Обработчики, ref и объекты стиля стабильны для каждого узла, поэтому `memo(NodeCard)` действительно пропускает неизменённые карточки.

**Перетаскивание.** Во время перетаскивания карточка показывается локально, граф меняется один раз при отпускании. Это одна запись истории. Отмена жеста (`pointercancel`) граф не трогает.

**Производные данные.** Они кэшируются на версию графа.

## Замеры

Headless Chromium, 1 ядро, без GPU. Абсолютные значения пессимистичны, сравнивать стоит соотношения. Единица — миллисекунды работы главного потока на один кадр прокрутки колесом.

| Сценарий | 0.7.0-rc.4 | после шага 1 |
|---|---|---|
| Лист, 300 узлов / 900 связей | ~19–35 | ~3 |
| Лист, 1000 / 3000 | ~80–100 (JS ~50) | ~14–23 (JS < 2) |
| Лист, 1000 / 5000 | ~120 | ~29 |
| Лист из 20 узлов в проекте 1000 / 3000 на 50 листах | ~23–26 | ~2 |
| Обзор, 1000 / 3000 на 10 листах | ~66–75 | ~29–32 |
| Перетаскивание карточки, 1000 / 3000, на одно движение | ~110 | ~45 |

Оставшееся время — отрисовка браузером DOM и SVG. Оно пропорционально числу элементов на экране, а не размеру проекта. Следующие шаги:

## Проверка

```
npm run build
npm i -D playwright && npx playwright install chromium   # один раз, локально
node scripts/perf-bench.mjs dist/index.html --check
```

Проверка падает, если карточки заново измеряются во время жеста, или если скрипт на кадр листа 1000/3000 дороже 8 мс. На rc.4 она падает на всех сценариях листа, после шага 1 проходит.

Не делайте `will-change: transform` слоем по умолчанию. В программной композиции это вызвало лавину композитных слоёв и ухудшило результат; проверять только на реальных устройствах.


## 0.8.0: хранение, сцена и фоновые задачи

Числа выше относятся к историческим версиям и средам; они не подтверждают FPS текущей сборки. Актуальные измерения браузера должны быть получены командой `npm run test:perf` и сохранены из CI; их нельзя подменять jsdom.

- IndexedDB получает structured clone без JSON.stringify на нормальном пути, в простое с timeout 1 с; незавершённая запись не помечает более поздние правки сохранёнными.
- `loadGraph` резервирует ID связей в Set. `buildIndex` хранит локальные и граничные связи по листам; lint и ссылки используют индекс. Время зависит и от числа членств, а не только объектов.
- `measureLayout` ищет перекрытия и пересечения связей с узлами через пространственную сетку. Плотные наложения всё ещё требуют много точных проверок; сетка не превращает любую сцену в линейную.
- В сценах больше 200 узлов работает отсечение с запасом 320 экранных пикселей; набор обновляется после движения на 180 пикселей или заметного изменения масштаба. Кривые проверяются по охватывающим прямоугольникам; повёрнутые фигуры получают расширенные границы. Выбранные/редактируемые узлы удерживаются.
- Более 500 узлов при масштабе <0.35 рисуются Canvas; читаемый масштаб возвращает DOM. Слои SVG и DOM не дублируют тысячи внутренних связей. В обзоре компактные листы объединяют пути, сохраняя приглушение; сцены переиспользуются при изменении камеры.
- Три медленных кадра (>24 мс) временно отключают второстепенные детали; качество восстанавливается после жеста. Постоянного will-change нет.
- Native JSON больше 1 МиБ и оптимизация проектов больше 300 узлов используют встроенный Worker. Отмена завершает worker; при недоступности используется прежний путь. DOMParser-импорты остаются в основном потоке. Силовая раскладка и lint не перенесены без отдельного подтверждения выигрыша.

`perf-bench` включает 10 000 узлов / 30 000 связей. Он проверяет смысловые количества после фильтра и число DOM-карточек в Canvas; разрешает появление новых карточек на границе отсечения. Прежние отношения времени фильтрованного/полного кадра перестали быть gate: сравнивались бы разные renderer-режимы. Абсолютное время и режим выводятся в журнал. Бюджет скрипта 8 мс для сценариев 1000/3000 сохранён; его прохождение в текущей версии требует Chromium.
