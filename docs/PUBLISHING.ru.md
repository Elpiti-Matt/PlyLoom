## Pages

После объединения обновления откройте **Actions → Publish demo to GitHub Pages → Run workflow**, выберите **main**, запустите и дождитесь зелёного результата. `pages.yml` не публикует по push. Если Pages требует настройки, проверьте **Settings → Pages → Source → GitHub Actions**; действующие настройки не нужно пересоздавать без причины. [Официальный порядок](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

После публикации проверьте фактический сайт и сценарии [QA-MANUAL](QA-MANUAL.md). Локальные тесты и сборка не подтверждают успешную публикацию.

## Статистика посещений Pages

Счётчик Яндекс Метрики: **112587397**. Адрес: **https://elpiti-matt.github.io/PlyLoom/**.

После обычной сборки `node scripts/prepare-pages.mjs` создаёт отдельный `dist/pages/index.html` со счётчиком и разрешениями CSP для его соединений. Workflow Pages публикует только эту папку. `demo/index.html`, `demo/SHA256SUMS` и автономный `dist/index.html` не изменяются. Для скачиваемых релизов используйте файл из `demo`, а не HTML, сохранённый с опубликованного сайта.

Счётчик загружается только по HTTPS на точном адресе этого демо (также допускается `index.html`). На `file://`, localhost, другом домене и в другом проекте он не запускается. Для публикации форка измените `SITE_URL` и `COUNTER_ID` в `scripts/prepare-pages.mjs` на собственные значения.

При открытии отправляется один просмотр. Наш вызов Метрики передаёт постоянные URL и заголовок PlyLoom, а для источника перехода — только домен с протоколом. В данные вызова не включаются название карты, тексты узлов, поисковая строка, параметры и фрагмент URL. Вебвизор, карты кликов, отслеживание ссылок/хеша, ecommerce, таймер отказов и Яндекс Тег Менеджер выключены. Метрика остаётся сторонней аналитикой и обрабатывает технические сведения о посетителе и браузере; отключённый Вебвизор не означает отсутствия сбора данных.

В настройках счётчика оставьте **«Вебвизор, карта скроллинга, аналитика форм»** выключенным. Для базовой посещаемости также не включайте автоматические цели и дополнительные настройки отслеживания контактных данных. Можно включить **«Ограниченный режим»**: посещаемость и источники сохранятся, часть рекламных и демографических отчётов будет недоступна. Поле адреса сайта: `elpiti-matt.github.io/PlyLoom/` без `https://`.

После успешной публикации откройте сайт, затем в Метрике **Настройки → Счётчик → Проверка счётчика** проверьте установку. После обработки визита проверьте отчёт о посещаемости. Блокировщики и сетевые ограничения могут не пропустить счётчик; приложение продолжает работать независимо от него. Данные собираются после установки, прошлые посещения и офлайн-запуски не восстанавливаются. Наличие номера в коде не подтверждает доступ владельца к отчётам: счётчик должен находиться в вашем аккаунте.

`node scripts/test-pages.mjs` проверяет настоящий сгенерированный код, ограничение адреса, отсутствие данных карты в явном событии, один просмотр, повторный запуск, отказ загрузки скрипта и неизменность офлайн-файлов. Проверки не отправляют пробные визиты в Метрику; появление настоящего визита в отчёте проверяется после публикации.

Официальные инструкции: [установка счётчика](https://yandex.ru/support/metrica/ru/general/creating-counter), [настройки](https://yandex.ru/support/metrica/ru/general/counter-general), [параметры инициализации](https://yandex.ru/support/metrica/ru/code/counter-initialize), [отправка просмотра](https://yandex.ru/support/metrica/ru/objects/hit), [CSP](https://yandex.ru/support/metrica/ru/code/install-counter-csp).

## Состав и настройки

Архив не содержит `.git`, `node_modules`, `dist` и временные файлы проверок. История и настройки аккаунта остаются в существующем репозитории. Закрытые правила веток, права, секреты и административные параметры Pages не проверены. `REPOSITORY.json` задаёт локальные ссылки. Состояние внешнего репозитория в этой поставке не проверялось.

`python scripts/configure_repo.py Elpiti-Matt --repo PlyLoom` обновляет локальные ссылки и ничего не публикует. `scripts/github_stats.py Elpiti-Matt/PlyLoom` читает скачивания release assets; бейдж считает файлы релизов, а не пользователей. Эти скрипты не входят в автономный HTML.

## Однозначный источник демо

`npm run build` создаёт `dist/index.html`, копирует те же байты в `demo/index.html` и обновляет `demo/SHA256SUMS`. Коммитите исходники и оба demo-файла вместе после `npm test`, сборки и `npm run test:release -- --static`. Не подменяйте демо проверочным HTML с кнопкой тестовых данных. `test:release` проверяет равенство dist/demo и SHA256.

Checks сохраняет автономный файл как артефакт. Опциональный ввод `browser` при ручном запуске включает Playwright, проверку настоящего HTML на 1440/390 px и perf-bench; переменная репозитория `PLYLOOM_BROWSER_CHECKS=true` включает эту задачу также по push/PR. Ошибки команд не скрываются, логи и снимки сохраняются отдельным артефактом. Pages публикуется отдельно и вручную; успешная локальная сборка не означает публикацию.
